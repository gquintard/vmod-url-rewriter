# vmod-redir Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Varnish vmod (`redir`) that loads exact/wildcard/regex rewrite rules from a YAML file and returns the output of the first matching rule.

**Architecture:** Cargo workspace modelled on `~/work/vmod-acls`. `redir-rules` is a pure Rust crate (parse, validate, first-match linear scan, reporting which rule matched). `vmod_redir` is a thin varnish-rs wrapper exposing `redir.rules(path)` and `.lookup(s)`, logging every lookup.

**Tech Stack:** Rust 2024, `varnish = "0.8"`, `regex = "1"`, `serde` + `serde_norway = "0.9"` (maintained `serde_yaml` fork), `criterion`, VTC via `varnish::run_vtc_tests!`.

**Spec:** `docs/superpowers/specs/2026-11-20-redir-design.md`

## Global Constraints

- Varnish 9.0 / 9.1; `varnish = "0.8"`; edition 2024; `rust-version = "1.90.0"`; license BSD-3-Clause; author `Guillaume Quintard <guillaume.quintard@gmail.com>`; repository `https://github.com/varnish-rs/vmod-redir`.
- Workspace lints copied from `vmod-acls` (`clippy::pedantic` warn, `unused_qualifications` warn).
- `redir-rules` has no varnish dependency.
- First match wins, in file order. Linear scan, but the scan is not visible in `redir-rules`' public API.
- The vmod never deals with status codes, hosts or URLs: string in, string out.
- Any invalid rule fails the whole load; all problems reported at once. No unreachable-rule detection: trust the user.
- `output` is the full redirect target; VCL copies it into `Location` untouched.
- Every `.lookup()` writes one `VCL_Log` record: which rule matched, or that none did.
- `just ci-test` must pass (fmt, clippy with `-D warnings` in CI, tests).

## Review Focus

1. **NULL input** (`rules.lookup(req.http.missing)`): returns NULL, no panic, no VCL failure. → Task 4 VTC `lookup.vtc`.
2. **Empty, whitespace-only or comment-only YAML file**: valid, zero rules (serde would reject a null document as a sequence). → Task 1 test `empty_documents_are_valid`.
3. **`$1foo` in a regex output**: `Captures::expand` reads it as group `1foo`, which expands to empty. This is the documented behavior; `${1}foo` is the fix. Pin it in a test and say it in API.md. → Task 3 test `dollar_name_greediness`.
4. **Multibyte UTF-8 around `*`** (`example.com/é*/ü`): matches by string pieces, never slices inside a char. → Task 2 test `wildcard_utf8`.

### Task 1: Workspace, loading and exact rules

**Files:**
- Create: everything under "copied" above, `Cargo.toml`, `justfile`, `redir-rules/Cargo.toml`, `redir-rules/src/lib.rs`, `redir-rules/src/load.rs`
- Test: `redir-rules/src/load.rs` (`#[cfg(test)] mod tests`), `redir-rules/src/lib.rs` tests

**Interfaces:**
- Produces (public, `redir_rules`):
  ```rust
  pub struct Rules { /* private: Vec<Rule> */ }
  impl Rules {
      pub fn from_yaml(text: &str) -> Result<Rules, LoadError>;
      pub fn lookup<'a>(&'a self, s: &str) -> Option<Match<'a>>;
      pub fn len(&self) -> usize;
      pub fn is_empty(&self) -> bool;
  }
  #[derive(Debug, PartialEq)] pub struct Match<'a> { pub index: usize /* 1-based */, pub kind: Kind, pub pattern: &'a str, pub output: Cow<'a, str> }
  #[derive(Debug, Clone, Copy, PartialEq, Deserialize)] #[serde(rename_all = "lowercase")] pub enum Kind { Exact, Wildcard, Regex } // Display: "exact" / "wildcard" / "regex"
  #[derive(Debug, PartialEq)] pub enum LoadError { Yaml(String), Rules(Vec<RuleError>) }
  #[derive(Debug, PartialEq)] pub struct RuleError { pub index: usize /* 1-based */, pub kind: RuleErrorKind }
  #[derive(Debug, PartialEq)] pub enum RuleErrorKind { EmptyMatch, EmptyOutput, InvalidRegex(String) }
  ```
  `LoadError` implements `Display` and `std::error::Error`. Display strings (exact):
  - `LoadError::Yaml(m)` → `invalid YAML: {m}`
  - `RuleError` → `rule #{index}: {kind}`, kinds: `empty match`, `empty output`, `invalid regex: {e}`
  - `LoadError::Rules(v)` → each `RuleError` on its own line, joined with `\n`.
- Produces (crate-internal): `pub(crate) struct Rule { pub matcher: Matcher, pub output: String }`, `pub(crate) enum Matcher { Exact(String), Wildcard(glob::Glob), Regex(regex::Regex) }`. Task 1 only creates `Exact`; Tasks 2 and 3 add the other variants.

```rust
#[test] fn wildcard_trailing() {
    let g = Glob::new("example.com/trolo/*");
    assert!(g.is_match("example.com/trolo/"));
    assert!(g.is_match("example.com/trolo/a/b.html"));
    assert!(!g.is_match("example.com/trolo"));
    assert!(!g.is_match("xexample.com/trolo/"));
}
#[test] fn wildcard_anywhere() {
    let g = Glob::new("*.example.com/old/*");
    assert!(g.is_match("www.example.com/old/x"));
    assert!(g.is_match(".example.com/old/"));
    assert!(!g.is_match("example.com/old/x"));
    let g = Glob::new("a*b*c");
    assert!(g.is_match("abc")); assert!(g.is_match("aXbYbZc")); assert!(!g.is_match("abcX")); assert!(!g.is_match("ac"));
    let g = Glob::new("ab*ba");
    assert!(!g.is_match("aba")); // prefix and suffix must not overlap
    assert!(g.is_match("abba"));
}
#[test] fn wildcard_stars_only() {
    for p in ["*", "**"] { assert!(Glob::new(p).is_match("")); assert!(Glob::new(p).is_match("anything")); }
}
#[test] fn wildcard_no_star_is_equality() {
    assert!(Glob::new("a/b").is_match("a/b")); assert!(!Glob::new("a/b").is_match("a/bc"));
}
#[test] fn wildcard_utf8() {
    let g = Glob::new("example.com/é*/ü");
    assert!(g.is_match("example.com/é/ü")); assert!(g.is_match("example.com/éàà/ü")); assert!(!g.is_match("example.com/e/ü"));
}
```

And in `lib.rs`: `wildcard_output_drops_tail` — rules `[wildcard example.com/trolo/* → trololo.com]`, `out(&r, "example.com/trolo/a/b.html").as_deref() == Some("trololo.com")`.

- [ ] **Step 2: Run** `cargo test -p redir-rules`. Expected: FAIL.

- [ ] **Step 3: Implement `Glob`.** Split the pattern on `*`. No star: equality. Otherwise the first piece must be a prefix and the last piece a suffix of `s`, with `first.len() + last.len() <= s.len()`; each middle piece is found with `str::find` leftmost, in order, in what lies between (greedy leftmost is correct for star-only globs). Use `strip_prefix`/`strip_suffix`/`find` only, never index arithmetic on chars. Wire the `Wildcard` arm in `load.rs` and `lookup`.

    let r = Rules::from_yaml(r"- {type: regex, match: 'example\.com/index(fr|en)$', output: 'trololo.com/index$1'}").unwrap();
    assert_eq!(out(&r, "example.com/indexfr").as_deref(), Some("trololo.com/indexfr"));

### Task 4: The vmod

**Files:**
- Create: `vmod_redir/Cargo.toml`, `vmod_redir/src/lib.rs`, `vmod_redir/API.md` (generated), `vmod_redir/tests/basic.vtc`, `vmod_redir/tests/lookup.vtc`, `vmod_redir/tests/errors.vtc`

**Interfaces:**
- Consumes: `redir_rules::{Rules, LoadError}`.
- Produces (VCL):
  ```rust
  #[varnish::vmod(docs = "API.md")]
  mod redir {
      impl Rules {   // vmod struct `Rules` wrapping `redir_rules::Rules` (import it as `RuleSet`)
          pub fn rules(ctx: &mut Ctx, #[vcl_name] name: &str, path: &str) -> Result<Self, VclError>;
          pub fn lookup(&self, ctx: &mut Ctx, #[required] s: Option<&str>) -> Option<String>;
      }
  }
  ```
  Error strings (exact): unreadable file → `{name}: cannot read {path}: {io error}`; load error → `{name}: {path}: {LoadError}`. On success log `LogTag::VclLog`: `{name}: loaded {n} rules from {path}`. Each lookup logs one `LogTag::VclLog` record (exact formats, values printed as-is, no escaping):
  - hit: `{name}: rule #{index} ({kind} "{pattern}") matched "{s}", output "{output}"`
  - miss: `{name}: no rule matched "{s}"`
  - NULL input: `{name}: no rule matched NULL` (my call)

  `path` is used as given (relative paths resolve against varnishd's working directory; say so in the doc comment). Doc comments document the VCL interface, as in vmod-acls, including the `$1foo` vs `${1}foo` pitfall and a full `vcl_recv`/`vcl_synth` example from the spec. `lookup(NULL)` → NULL.

- [ ] **Step 1: Write failing VTCs.** Rule files are written with `shell` into `${tmpdir}`, e.g.:

```
shell {cat > ${tmpdir}/rules.yaml <<'EOF'
- {type: exact, match: example.com/index.html, output: 'https://trololo.com/tralala.php'}
- {type: wildcard, match: 'example.com/trolo/*', output: 'https://trololo.com'}
- {type: regex, match: 'example\.com/index(fr|en)$', output: 'https://trololo.com/index$1'}
EOF}
```

  - `basic.vtc`: the spec's VCL example verbatim (path → `${tmpdir}/rules.yaml`). Requests with `-hdr "host: example.com"` to `/index.html`, `/trolo/a/b.html`, `/indexen` expect 301 and `location` `https://trololo.com/tralala.php`, `https://trololo.com`, `https://trololo.com/indexen`; `/nope` expects the backend's 200. A `logexpect l1 -v v1 -g raw` checks the records: `VCL_Log` `rules: loaded 3 rules from`, `rules: rule #2 (wildcard "example.com/trolo/*") matched "example.com/trolo/a/b.html", output "https://trololo.com"`, `rules: no rule matched "example.com/nope"`.
  - `lookup.vtc`: `set resp.http.r = rules.lookup(req.http.missing);` then `expect resp.http.r == ""` (a NULL assigned to a header becomes empty) and a `logexpect` for `rules: no rule matched NULL`; an empty file loads and every lookup gives `""`.
  - `errors.vtc` (`-errvcl` substring checks): missing file → `r: cannot read`; invalid YAML → `invalid YAML`; invalid regex → `rule #1: invalid regex`; two empty fields → both `rule #1: empty match` and `rule #2: empty output` (two `-errvcl` runs on the same file).
